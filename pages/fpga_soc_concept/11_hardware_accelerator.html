Hardware Accelerator 구조

CPU가 제어를 담당하고 RTL Datapath가 병렬 연산을 담당하는 Accelerator의 기본 구조를 Register Map과 AXI 관점에서 설명합니다.

AcceleratorControl PathData PathAXI4-LiteBRAMStream

CPU 역할

설정·시작·상태 확인을 담당합니다.

RTL 역할

반복 연산을 병렬 Datapath로 처리합니다.

Interface

Control은 AXI4-Lite, Data는 BRAM/Stream으로 분리할 수 있습니다.

이 챕터의 위치

FPGA 구조→RTL→SoC→AXI / IP→Accelerator / NPU
SECTION 01

CPU + Accelerator 구조

MicroBlaze → AXI4-Lite Control/Status Register → Accelerator · Data는 BRAM 또는 AXI4-Stream으로 분리
SECTION 02

Control Register 예

OffsetRegister의미
0x00CTRLstart, reset, mode
0x04STATUSbusy, done, error
0x08INPUT_ADDR입력 Buffer 정보
0x0COUTPUT_ADDR출력 Buffer 정보

위 Register Map은 구조 설명용 예시이며 실제 구현 시 RTL과 Software Header의 주소 정의를 동일하게 유지해야 합니다.

SECTION 03

Control Path와 Data Path를 분리하는 이유

  • CPU는 복잡한 조건 판단과 System Control에 유리
  • RTL은 정해진 연산을 Cycle 단위로 병렬화 가능
  • Register Interface를 고정하면 Datapath 내부 구현을 바꿔도 Software 영향 최소화
SECTION 04

성능 평가

Accelerator를 만들었다고 자동으로 빨라지는 것은 아닙니다. Data 이동 시간이 계산 시간보다 길 수 있으므로 Latency, Throughput, Memory Bandwidth, Clock, Resource 사용량을 함께 측정해야 합니다.

Latency 구성의미
SetupRegister 설정·Start 명령
Data Move입력/출력 데이터 전달
ComputeAccelerator 실제 연산
TotalSetup + Data Move + Compute
SUMMARY
