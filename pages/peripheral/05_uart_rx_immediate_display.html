UART RX 1문자 즉시 표시 · RX Display Register 수정

기존 RX+TX 통합 구조는 그대로 유지하고, basys3_uart_rx_tx_top.v의 RX 표시 Register만 수정합니다. 이제 LF를 기다리지 않고 rx_valid가 발생하면 최근 수신 문자를 LED에 즉시 표시합니다.

Minimal Change rx_valid Immediate Display LF Frame Basys3 LED

기존

line_frame_valid, 즉 LF가 들어와야 수신 문자 표시가 갱신되었습니다.

변경

rx_valid 발생 즉시 rx_data를 LED 표시 Register에 저장합니다.

유지

frame_valid_latched는 계속 LF 기준 Frame 완료 표시로 사용합니다.

STEP 02

2. 기존 동작의 문제

PC에서 'A' 전송 → rx_data = 0x41 → LF 없음 → line_frame_valid = 0 → LED 표시 Register 갱신 안 됨

기존 Chapter 04에서는 display_last_data를 line_frame_valid 시점에만 갱신했습니다. 따라서 Line Frame 종료 문자인 LF(0x0A)가 오기 전까지 한 문자 수신 결과를 바로 볼 수 없습니다.

3. 수정 후 역할 분리

신호역할

4. 수정하지 않는 Core

uart_core.v

UART 수신 알고리즘, FIFO, Line Buffer, TX Core를 다시 설계하지 않습니다. 정상 동작하는 기존 회로를 유지하고 표시 정책만 Top에서 변경합니다.

STEP 05

5. RX 표시 Register 수정

always @(posedge clk) begin
    if (reset) begin
        display_div         <= 26'd0;
        display_last_data   <= 8'd0;
        frame_valid_latched <= 1'b0;
    end
    else begin
        display_div <= display_div + 1'b1;

        // 수신 1Byte가 유효하면 즉시 표시
        if (rx_valid) begin
            display_last_data <= rx_data;
        end

        // LF는 Frame 완료 표시만 담당
        if (line_frame_valid) begin
            frame_valid_latched <= 1'b1;
            display_div         <= 26'd0;
        end
        else if (display_div[25]) begin
            frame_valid_latched <= 1'b0;
        end
    end
end

STEP 08

8. LED 표시 기준과 검증 메모

LED이번 기능에서의 의미
LED[7:0]최근 수신 문자 ASCII 값
LED8LF 기준 Frame 완료 표시
LED9문자열 수신 중 상태
LED10Overflow 또는 Discarding 상태
검증 메모: 원본 05 자료의 LED 표에는 LED[15:11]을 “사용하지 않음”으로 적었지만, 같은 자료에서 명시한 수정 범위는 RX 표시 Register 블록 하나뿐입니다. 따라서 이번 구현에서는 Chapter 04의 기존 TX/RX 상태 LED11~LED15 연결을 임의로 삭제하지 않고 그대로 유지했습니다.

핵심 정리

  • 기존 UART RX+TX 구조는 유지하고 Top의 RX 표시 Register만 수정합니다.
  • rx_valid 발생 시 rx_data를 LED에 즉시 표시합니다.
  • LF는 더 이상 문자 표시 조건이 아니며 Line Frame 완료 조건으로만 사용합니다.
  • A 한 글자만 수신해도 LED[7:0]에서 0x41을 바로 확인할 수 있습니다.
  • 정상 Core를 불필요하게 수정하지 않고 표시 정책만 바꾸는 최소 수정 방식입니다.
