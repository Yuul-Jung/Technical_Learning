RTL 주변기기 회로설계 · 04

UART RX + TX 통합 · uart_core RTL 실습

앞에서 만든 UART RX Core와 UART TX Core를 하나의 uart_core로 묶고, Baud Rate 설정을 상위 Parameter로 통합합니다. RX 문자열 처리와 보드 버튼·LED는 Core 밖에 유지합니다.

UART RX + TX uart_core Parameter RX Line Buffer TX FIFO

RX

RsRx → uart_rx_core → RX FIFO → Line Buffer 구조를 유지합니다.

TX

버튼 Pulse가 ASCII 문자를 TX FIFO에 넣고 uart_tx_core가 RsTx로 송신합니다.

Core 경계

보드 버튼·LED·Line Buffer는 uart_core 안에 넣지 않습니다.

중요: uart_core는 순수 UART 송수신 기능만 담당합니다. 보드 버튼, LED, BRAM Line Buffer는 포함하지 않습니다. 이 경계를 유지해야 이후 AXI4-Lite(에이엑스아이 포 라이트, 경량 메모리맵 버스) Wrapper로 확장하기 쉽습니다.
STEP 03

3. Baud Rate 설정을 한 곳에서 관리

parameter CLK_FREQ  = 100_000_000;
parameter BAUD_RATE = 9600;

parameter RX_OVERSAMPLE = 16;

parameter CLKS_PER_SAMPLE =
    CLK_FREQ / (BAUD_RATE * RX_OVERSAMPLE);

parameter CLKS_PER_BIT =
    CLK_FREQ / BAUD_RATE;
RX: 100,000,000 ÷ (9,600 × 16) → 약 651
TX: 100,000,000 ÷ 9,600 → 약 10,416
원본 단계는 정수 나눗셈 결과를 Parameter로 전달합니다. 100MHz/9600의 정확한 값은 정수가 아니므로 실제 생성값에는 작은 Baud 오차가 존재합니다. 이번 페이지에서는 원본 계산 구조를 변경하지 않았습니다.
STEP 04

4. uart_rx_core — CLKS_PER_SAMPLE 외부 Parameter화

module uart_rx_core #(
    parameter CLKS_PER_SAMPLE = 651
)(
    ...
);

uart_baud_tick_gen #(
    .CLKS_PER_SAMPLE(CLKS_PER_SAMPLE)
) u_uart_baud_tick_gen (
    .clk   (clk),
    .reset (reset),
    .tick  (sample_tick)
);

RX 알고리즘이나 FIFO 구조를 다시 만드는 것이 아니라, 기존 RX Core가 상위 uart_core에서 계산된 Sample Count를 받을 수 있도록 Parameter 전달 구조만 추가합니다.

STEP 05

5. uart_core — RX Core와 TX Core 통합

rx_serial→ uart_rx_core→ rx_data / valid / ready
tx_wr_data / en→ uart_tx_core→ tx_serial 
uart_rx_core #(
    .CLKS_PER_SAMPLE(CLKS_PER_SAMPLE)
) u_uart_rx_core (...);

uart_tx_core #(
    .CLKS_PER_BIT(CLKS_PER_BIT)
) u_uart_tx_core (...);

두 Core는 같은 clk, reset, CLK_FREQ, BAUD_RATE 체계에서 동작하지만 RX 데이터와 TX 데이터의 기능 경로는 독립되어 있습니다.

STEP 06

6. Basys3 Top — RX와 TX를 동시에 연결

RX 경로

PC → RsRx → uart_core → rx_data/rx_valid → rx_bram_line_buffer → LF Frame 검출 → LED

TX 경로

btnC → button_debounce_pulse → ASCII a,b,c,...,z → tx_wr_data / tx_wr_en → uart_core TX FIFO → RsTx → PC 
if (btn_pulse && !tx_full) begin
    tx_wr_data <= ascii_reg;
    tx_wr_en   <= 1'b1;

    if (ascii_reg == 8'h7A)
        ascii_reg <= 8'h61;
    else
        ascii_reg <= ascii_reg + 1'b1;
end
이번 단계에서는 Echo를 수행하지 않습니다. RX로 받은 문자를 TX로 다시 보내는 회로는 아직 연결하지 않습니다. RX와 TX가 한 Top에서 동시에 동작하는 통합 구조까지만 확인합니다.
STEP 07

7. 보드 동작 확인

조작예상 동작
btnU전체 UART RX/TX Reset
PC → RsRx 문자열 + LF마지막 문자 LED[7:0] 표시, Frame 완료 표시
btnC 1회a 송신
btnC 2회b 송신
계속 누름c ... z → a 순환 송신
위 내용은 원본의 보드 확인 절차입니다. 여기에서 실제 Vivado 실행 결과를 새로 생성한 것은 아니므로 홈페이지에서는 예상 동작 / 보드 확인 기준으로 표시합니다.
STEP 08

8. LED 상태와 XDC 사용 기준

LED표시 내용
LED[7:0]RX 마지막 실제 문자
LED8RX Frame 완료 상태
LED9RX 문자열 수신 중
LED10Line Buffer Overflow 또는 Discarding
LED11TX FIFO Empty
LED12TX FIFO Full
LED13TX Busy
LED14TX Done Pulse
LED15RX Frame Error 또는 FIFO Overrun

XDC는 기존 파일을 그대로 사용하고 새 XDC를 만들지 않습니다. 필요한 Top 외부 포트는 clk, btnC, btnU, RsRx, RsTx, led[15:0]입니다.

원본 단계04에는 별도 Testbench가 제공되지 않았습니다. 따라서 실제 Simulation Output을 임의로 만들어 넣지 않았습니다.

핵심 정리

  • UART RX와 TX를 하나의 재사용 가능한 uart_core로 묶습니다.
  • CLK_FREQ와 BAUD_RATE에서 RX Sample Count와 TX Bit Count를 계산합니다.
  • RX Line Buffer와 버튼 Debounce는 uart_core 밖에 유지하여 UART Core의 책임 범위를 분리합니다.
  • RX는 문자열 + LF를 처리하고 TX는 버튼 입력으로 a~z 문자를 송신합니다.
  • 이번 단계는 RX와 TX의 통합 단계이며 Echo 기능은 아직 연결하지 않습니다.
  • 이 구조는 이후 UART Echo, Command/Response, Register Map, AXI Wrapper 확장의 기반이 됩니다.
