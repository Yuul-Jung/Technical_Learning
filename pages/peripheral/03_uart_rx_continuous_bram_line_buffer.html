RTL 주변기기 회로설계 · 03

UART RX 연속문자 · BRAM Line Buffer RTL 실습

02의 UART RX 1Byte 구조는 그대로 유지하고 FIFO 뒤에 64Byte Line Buffer를 추가합니다. LF(0x0A)를 문자열 Frame 종료 기준으로 사용하여 연속문자를 저장하고 frame_valid·frame_length·overflow·discarding 상태를 만듭니다.

UART RX BRAM Line Buffer LF 0x0A Frame Valid Overflow

재사용

기존 uart_rx_sync·Baud Tick·RX FSM·FIFO·Core는 수정하지 않습니다.

Frame

LF를 만나기 전까지 일반 문자를 저장하고 LF에서 한 줄 수신 완료를 알립니다.

Overflow

Buffer가 가득 차면 저장을 중단하고 LF가 올 때까지 이후 Byte를 버립니다.

STEP 02

2. 64Byte BRAM Line Buffer

parameter BRAM_DEPTH = 64;
parameter ADDR_WIDTH = 6;

(* ram_style = "block" *)
reg [7:0] bram_mem [0:BRAM_DEPTH-1];
1문자 = 1Byte
64Byte → 문자 64개 저장 공간
2^6 = 64 → 주소 폭 6bit

원본은 교육적으로 BRAM Line Buffer 구조로 사용합니다. 다만 작은 메모리는 Vivado 합성 결과에서 LUT RAM으로 구현될 수도 있음을 명시합니다.

3. 문자열 종료 기준 — LF = 0x0A

localparam LF = 8'h0A;
A → 저장
B → 저장
C → 저장
LF → 저장하지 않음 → Frame 완료
입력BRAM 동작결과

STEP 04

4. FIFO Read 제어권을 Line Buffer로 이동

02 단계의 Top은 다음 방식이었습니다.

assign rx_ready = rx_valid;

이번 단계에서는 Line Buffer가 FIFO를 읽습니다.

assign rx_ready = line_rx_ready;

Line Buffer 내부는 현재 항상 읽을 준비가 된 구조입니다.

assign rx_ready = rx_valid;
RX FIFO에 Byte 존재 → rx_valid=1 → line_rx_ready=1 → 1Byte 소비 → Line Buffer에서 Frame 조립
STEP 05

5. LF 감지와 frame_valid

else if (rx_data == LF) begin
    frame_valid_reg  <= 1'b1;
    frame_length_reg <= {1'b0, wr_addr};
    wr_addr          <= {ADDR_WIDTH{1'b0}};
    receiving_reg    <= 1'b0;
end

frame_valid는 1 Clock Pulse입니다. Frame 길이는 LF 자체를 제외하고 실제 저장된 문자 수만 출력합니다.

ABC + LF → BRAM[0]='A' → BRAM[1]='B' → BRAM[2]='C' → frame_valid=1 → frame_length=3
STEP 06

6. Overflow와 Discarding

if (wr_addr < BRAM_DEPTH - 1) begin
    bram_mem[wr_addr] <= rx_data;
    wr_addr <= wr_addr + 1'b1;
end
else begin
    bram_mem[wr_addr] <= rx_data;
    overflow_reg   <= 1'b1;
    discarding_reg <= 1'b1;
end
Buffer 가득 참 → overflow=1 → discarding=1 → 이후 Byte 저장하지 않음 → LF까지 버림 → LF에서 다음 Frame 준비
검증 메모: 원본 설명은 “64Byte를 초과하면 overflow”라고 표현하지만, 제공된 RTL은 64번째 문자를 마지막 주소에 저장하는 시점에 overflow_reg와 discarding_reg를 1로 만듭니다. 또한 overflow_reg는 LF에서 자동으로 0으로 지우지 않고 Reset까지 유지됩니다. 홈페이지에서는 원본 코드를 변경하지 않고 이 차이를 별도로 표시했습니다.

예상 동작 — ABC + LF

A  → BRAM[0]
B  → BRAM[1]
C  → BRAM[2]
LF → frame_valid 발생

last_data    → 0x43
frame_length → 3
overflow     → 0
discarding   → 0

frame_valid는 1 Clock Pulse라 LED에서 보기 어려우므로, Top에서는 별도 표시 Register에 저장하고 분주 Counter로 잠시 유지합니다.

STEP 08

8. Testbench 검증

원본 Testbench는 UART 비트 파형 전체 대신 FIFO에서 Byte가 나온 상황을 직접 만들어 Line Buffer 자체를 검증합니다.

task push_byte;
    input [7:0] data;
    begin
        @(posedge clk);
        rx_data  = data;
        rx_valid = 1'b1;

        @(posedge clk);
        rx_valid = 1'b0;
        rx_data  = 8'h00;
    end
endtask

핵심 정리

  • 03 단계에서는 02의 UART RX Core와 FIFO를 수정하지 않고 그대로 재사용합니다.
  • FIFO 뒤에 64Byte BRAM Line Buffer를 추가하여 Byte를 문자열 Frame으로 누적합니다.
  • LF(0x0A)를 Frame 종료 문자로 사용하며 LF 자체는 Buffer에 저장하지 않습니다.
  • LF 검출 시 frame_valid를 1 Clock 발생시키고 frame_length를 확정합니다.
  • Buffer가 가득 찬 이후에는 discarding 상태에서 LF까지 입력을 버립니다.
  • 이 구조는 이후 UART RX/TX 통합, Echo, Command Parser, Register Map으로 확장하기 위한 문자열 수신 계층입니다.
