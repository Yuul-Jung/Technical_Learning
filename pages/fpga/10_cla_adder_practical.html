STEP 01

1. 4비트 가산기와 Carry

4비트 Adder는 a[3:0], b[3:0], cin을 더하여 하위 4비트 결과 sum[3:0]과 최종 Carry cout을 출력합니다.

A[3:0] + B[3:0] + Cin → {Cout, Sum[3:0]}
1111
+0001
-----
10000
출력값의미
sum0000하위 4비트 결과
cout14비트를 초과한 최상위 비트
STEP 02

2. Ripple Carry 방식

Ripple Carry Adder는 각 자리에서 발생한 Carry가 다음 자리로 순차 전달됩니다.

C0 → C1 → C2 → C3 → Cout
항목특징
장점구조가 단순하고 계층적 Full Adder 연결을 이해하기 쉽습니다.
단점비트 수가 증가하면 Carry 전달 단계가 길어져 지연이 커질 수 있습니다.
STEP 03

3. Carry Look-Ahead 원리

CLA(Carry Look-Ahead)는 Carry를 하위 비트부터 기다리지 않고 논리식으로 미리 계산합니다.

신호식의미
PropagateP = A ^ B이전 Carry를 다음 단계로 전달할 조건
GenerateG = A & B현재 비트 자체에서 Carry가 발생할 조건
c1 = g0 + p0·cin
c2 = g1 + p1·g0 + p1·p0·cin
c3 = g2 + p2·g1 + p2·p1·g0 + p2·p1·p0·cin
STEP 04

4. 원리 이해용 CLA 직접 구현

assign p = a ^ b;
assign g = a & b;

assign c1 = g[0] | (p[0] & cin);
assign c2 = g[1]
          | (p[1] & g[0])
          | (p[1] & p[0] & cin);

assign c3 = g[2]
          | (p[2] & g[1])
          | (p[2] & p[1] & g[0])
          | (p[2] & p[1] & p[0] & cin);

이 방식은 Carry Look-Ahead의 내부 원리를 확인하기에는 좋지만 비트 수가 커질수록 Carry 식이 빠르게 복잡해집니다.

비트 수직접 Carry 식 작성
4비트원리 설명에 적합
8비트복잡해짐
16비트매우 복잡함
32비트직접 전개가 비효율적
STEP 05

5. FPGA 실무형 + 연산자 작성

FPGA RTL에서 +는 소프트웨어 계산을 의미하는 것이 아니라 합성 가능한 가산기 하드웨어를 기술하는 연산자입니다.

module c_adder4_practical(
    input  [3:0] a,
    input  [3:0] b,
    input        cin,
    output [3:0] sum,
    output       cout
);

assign {cout, sum} = {1'b0, a} + {1'b0, b} + cin;

endmodule
원본 자료에서는 CLA 직접 전개는 원리 이해용, + 연산자 방식은 FPGA 실무형 작성 방식으로 구분합니다.
STEP 06

6. {cout, sum}과 비트폭

{cout, sum}은 Concatenation(컨캐터네이션, 비트 연결)으로 1비트 cout과 4비트 sum을 하나의 5비트 결과로 묶습니다.

{cout, sum}
= {cout, sum[3], sum[2], sum[1], sum[0]}

입력도 각각 1비트 확장하여 5비트 연산임을 명확히 합니다.

{1'b0, a} + {1'b0, b} + cin
15 + 1 → 5'b10000 → cout=1, sum=0000
STEP 07

7. 32비트로 확장

실무형 표현의 장점은 비트폭을 확장해도 구조가 거의 바뀌지 않는다는 점입니다.

module c_adder32(
    input  [31:0] a,
    input  [31:0] b,
    input         cin,
    output [31:0] sum,
    output        cout
);

assign {cout, sum} = {1'b0, a} + {1'b0, b} + cin;

endmodule
구분CLA 직접 전개실무형 + 연산자
코드 길이김짧음
원리 이해좋음추상화됨
확장성낮음높음
32비트 확장복잡함쉬움
STEP 08

8. Testbench로 Carry 경계 검증

initial begin
    a = 4'd0;  b = 4'd0;  cin = 1'b0; #10;
    a = 4'd3;  b = 4'd2;  cin = 1'b0; #10;
    a = 4'd7;  b = 4'd1;  cin = 1'b0; #10;
    a = 4'd8;  b = 4'd7;  cin = 1'b0; #10;
    a = 4'd15; b = 4'd1;  cin = 1'b0; #10;
    a = 4'd15; b = 4'd15; cin = 1'b0; #10;
    a = 4'd15; b = 4'd15; cin = 1'b1; #10;
    $finish;
end

특히 15+1, 15+15, 15+15+1처럼 4비트를 넘는 결과에서 sum과 cout이 올바르게 분리되는지 확인합니다.

핵심 정리

  • Ripple Carry는 구조가 단순하지만 Carry가 순차 전달됩니다.
  • Carry Look-Ahead는 Propagate와 Generate를 이용하여 Carry를 미리 계산합니다.
  • CLA Carry 식 직접 전개는 원리 이해에 적합하지만 비트폭이 커질수록 복잡해집니다.
  • FPGA RTL에서는 + 연산자를 이용해 합성 가능한 가산기를 간결하게 표현할 수 있습니다.
  • {cout, sum}을 사용하면 5비트 결과의 상위 Carry와 하위 4비트를 명확하게 분리할 수 있습니다.
  • 실무형 코드는 4비트에서 32비트로 쉽게 확장할 수 있습니다.
