STEP 02

2. DUT 원본 소스

module c_halfadder(
    input  in_a,
    input  in_b,
    output sum,
    output carry
);

assign sum   = in_a ^ in_b;
assign carry = in_a & in_b;

endmodule
in_a · in_b → XOR → sum
in_a · in_b → AND → carry
원본 자료의 DUT 회로 그림은 Notion 임시 파일 URL이므로 GitHub Pages에 직접 연결하지 않았습니다. 대신 소스와 신호 관계를 텍스트 구조로 유지했습니다.
STEP 03

3. Testbench 전체 코드

module tb_c_halfadder;

reg tb_a;
reg tb_b;

wire tb_sum;
wire tb_carry;

c_halfadder dut(
    .in_a(tb_a),
    .in_b(tb_b),
    .sum(tb_sum),
    .carry(tb_carry)
);

initial begin
    tb_a = 0; tb_b = 0; #10;
    tb_a = 0; tb_b = 1; #10;
    tb_a = 1; tb_b = 0; #10;
    tb_a = 1; tb_b = 1; #10;
    $finish;
end

endmodule

Testbench에는 외부 입력·출력 포트가 없으며, 내부에서 DUT 입력 자극을 만들고 DUT 출력을 관찰합니다.

STEP 04

4. reg와 wire의 역할

종류역할예
regTestbench가 직접 값을 변경하여 DUT에 입력을 공급하는 신호reg tb_a;
wireDUT가 계산한 출력 결과를 전달받는 연결 신호wire tb_sum;
Testbench가 값을 넣는 신호 → reg
DUT 출력에서 값을 받아오는 신호 → wire

핵심 정리

  • Testbench는 검증 환경이고 DUT는 실제 검증 대상 회로입니다.
  • Testbench 안에서 DUT Module을 Instance하여 검증합니다.
  • reg는 Testbench가 입력값을 직접 변경하는 신호입니다.
  • wire는 DUT 출력 결과를 전달받는 연결 신호입니다.
  • .포트명(연결신호명) 문법으로 DUT 포트와 Testbench 신호를 매핑합니다.
  • initial에서 입력 자극을 만들고 #10으로 입력 변경 사이 시간을 둡니다.
  • Simulation은 입력 생성 → DUT 전달 → 논리 연산 → 출력 → Testbench 관찰 흐름으로 이해합니다.
