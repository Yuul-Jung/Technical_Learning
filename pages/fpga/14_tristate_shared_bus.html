Tri-State Buffer · Shared Bus RTL 실습

0·1뿐 아니라 High-Z(Z) 상태를 사용하는 Tri-State Buffer를 이해하고, 두 데이터 소스가 하나의 Shared Bus를 선택적으로 사용하는 구조를 Verilog와 Simulation으로 확인합니다.

STEP 01

1. Tri-State Buffer란?

일반 Buffer는 출력이 0 또는 1이지만, Tri-State Buffer는 여기에 Z(High Impedance) 상태가 추가됩니다.

상태의미
0Low 출력
1High 출력
Z출력을 끄고 Bus에서 전기적으로 손을 뗀 상태

대표 74 시리즈 IC

IC기능
74125Quad Tri-State Buffer
74244Octal Buffer
74245Bus Transceiver
STEP 02

2. Z 상태와 X 상태

High-Z(Z)

출력 비활성 → Bus를 구동하지 않음 → 다른 장치가 Bus를 사용할 수 있음

Unknown(X)

X는 시뮬레이터가 논리값을 결정할 수 없는 상태입니다. 원본 자료에서는 Multiple Driver, Bus Contention, 초기화 안 됨, 충돌 상황을 대표 원인으로 설명합니다.

표현의미
4'bzzzz4비트 모두 High-Z
4'bxxxx4비트 모두 Unknown
STEP 03

3. Shared Bus 구조

Shared Bus는 여러 장치가 하나의 데이터 선을 공유하는 구조입니다. 원본 자료에서는 CPU Datapath, Memory Bus, SPI, UART, AXI로 이어지는 개념 연결을 제시합니다.

Device A↘Shared Bus→수신 회로
Device B↗Enable로 사용권 제어
이번 실습의 핵심은 두 입력 중 Enable된 데이터만 하나의 bus[3:0]에 나타나도록 만드는 것입니다.

STEP 05

5. Dataflow Modeling

원본에서는 assign과 조건 연산자로 Shared Bus를 표현합니다.

module p_tristate_bus(
    input [3:0] a,
    input [3:0] b,
    input en_a,
    input en_b,
    output [3:0] bus
);

assign bus =
    en_a ? a :
    en_b ? b :
    4'bzzzz;

endmodule
코드의미
en_a ? aA Enable 시 A를 Bus로 전달
en_b ? bA가 꺼져 있고 B Enable 시 B를 전달
4'bzzzz둘 다 비활성일 때 High-Z
검증 메모: 이 코드는 중첩 조건 연산자이므로 en_a가 우선권을 가집니다. 따라서 en_a=1, en_b=1이면 코드 의미상 A가 출력됩니다. 원본의 관찰표에는 이 경우 “X 가능 / Bus Contention”이라고 되어 있지만, 주어진 RTL 자체는 두 개의 독립 Driver가 아니라 우선순위 선택 구조입니다. 원본 코드는 변경하지 않고 이 차이를 명시합니다.
STEP 06

6. Testbench 작성

module tb_tristate_bus;

reg [3:0] a;
reg [3:0] b;
reg en_a;
reg en_b;
wire [3:0] bus;

p_tristate_bus dut(
    .a(a),
    .b(b),
    .en_a(en_a),
    .en_b(en_b),
    .bus(bus)
);

initial begin
    a = 4'b1010;
    b = 4'b0101;

    en_a = 0; en_b = 0; #10;
    en_a = 1; en_b = 0; #10;
    en_a = 0; en_b = 1; #10;
    en_a = 0; en_b = 0; #10;
    en_a = 1; en_b = 1; #10;

    $finish;
end

endmodule

Testbench는 Z 상태, A 선택, B 선택, 둘 다 OFF, 둘 다 ON 순으로 입력 조건을 변경합니다.

STEP 08

8. FPGA 내부 합성 구조

원본 자료의 중요한 포인트는 FPGA 내부에서는 실제 Tri-State Bus를 거의 사용하지 않고, Vivado가 내부 구조를 LUT·MUX 형태로 합성할 수 있다는 점입니다.

Tri-State RTL 표현 → Synthesis → 내부 LUT / MUX 구조

Vivado에서 다음을 확인합니다.

  • Run Behavioral Simulation — Z 상태와 선택 동작 확인
  • RTL Analysis → Open Elaborated Design
  • RTL Schematic에서 Enable과 Shared Bus 연결 구조 확인
  • 실제 Tri-State 구조인지 MUX 구조인지 비교
Tri-State→Shared Bus→Datapath→CPU 구조

핵심 정리

  • Tri-State Buffer는 0, 1, Z의 세 가지 출력 상태를 표현합니다.
  • Z는 Bus를 구동하지 않는 High Impedance 상태입니다.
  • Shared Bus에서는 Enable 신호로 어떤 데이터 소스가 Bus를 사용할지 제어합니다.
  • X는 값이 결정되지 않는 Unknown 상태이며 Multiple Driver나 충돌 상황에서 나타날 수 있습니다.
  • 원본 RTL의 중첩 조건 연산자는 실제로 en_a 우선 선택 구조이므로, 두 Enable이 동시에 1일 때 X가 아니라 A를 선택합니다.
  • FPGA 내부 Tri-State 표현은 합성 후 LUT·MUX 구조로 구현될 수 있으므로 RTL Schematic 확인이 중요합니다.
